# Head and neck movements v1

Stage 05.1a, 2026-10-23. Definitions and builders are in
`src/avatar_app/movement_library/joints.py`. `registry.CATALOG` now registers exactly
head.look, head.nod, head.shake, head.tilt and neck.lead, definition version 1. Test IDs
stay in the separate test catalog. Registration does not automatically grant a rig review.
No prompt interpretation, user-visible preset list or other Stage 05 family is added.

## Shared parameters and entry policy

All five IDs accept `duration_s` (number, seconds, default 1, range 0.8..3), `hold_s`
(number, seconds, default 0.2, range 0..1), and `return_policy` (preserve_end or
return_to_entry). Duration is **per transition/stroke**, rather than the duration of
an entire shake or return. Timing rounds upward to the next 30-fps boundary, by less
than one frame, so every phase goal has an actual execution sample. Zero hold stays
zero, except a world-look return retains one endpoint frame for measured arrival.

Default return is preserve_end for head.look and return_to_entry for the other IDs.
Return means the supplied measured entry, including a bent/turned non-neutral head.
No named-neutral reset is performed. Explicit zero is preserved. Tracks own only head,
or head and the actual neck for an articulated neck.lead. Builders carry all asserted
entry contacts with the same anchors/surfaces; they do not acquire different support,
move the torso/root to reach a target, or write limb targets.

Entry must have all required measured controls in the profile's declared frames, and
each authored destination must fit that profile's angular limits. Requirements record
the measured values used to author the fragment. Invalid target/duration/type/capability
fails explicitly; out-of-range input is not clamped. A target that becomes unreachable
during an external parent motion fails the shared transaction and preserves the old result.

Use `registry.parameter_schema(definition)` for the authoritative generated schema.
The test outputs also save it as `artifacts/stages/05.1a/<rig>/schemas.json`.

## IDs and semantics

| ID | Additional parameters | Frames, phases and ownership |
| --- | --- | --- |
| head.look | yaw default 25, -60..60 degrees; pitch default 0, -40..40 degrees; frame torso/world, default torso; target nullable world-metre vector, component bounds -20..20 | Owns head orientation. Torso mode reaches the requested combined swing/twist orientation relative to the uppermost calibrated torso frame, with level roll. World mode needs a target point, omits explicit yaw/pitch, approaches it and continues tracking it as the parent moves. Optional return restores entry orientation in the original declared frame. |
| head.nod | angle default 20, -35..35 degrees | One pitch stroke relative to measured entry, hold, then optional return. Positive nods forward; negative moves backward. Untargeted head yaw/roll stay unchanged. |
| head.shake | angle default 20, 0..35 degrees; direction left/right, default left | One side-to-side yaw cycle: entry plus signed angle, hold, entry minus signed angle, hold, optional return. Direction selects the first side; there is no repeat engine. |
| head.tilt | angle default 20, -35..35 degrees | One roll stroke relative to entry. Positive tilts right, negative left. Head yaw/pitch, torso and limbs remain unchanged. |
| neck.lead | yaw default 30, -50..50 degrees; pitch default 0, -30..30 degrees; neck_share default 0.4, 0.2..0.6; neck_policy require_neck/head_only, default require_neck | Neck takes the declared fraction of the requested local angular change first; head begins 8 frames later and takes the remainder. Only the requested yaw/pitch components are distributed. Both return to their own measured entries when requested. Head-only mode has no stagger or neck track and receives an explicit approximation landmark. |

Neck distribution is in calibrated local scalar components. It is not a promise that
two arbitrary multi-axis joint rotations add as Euler angles. Every owned component has
an independently measured phase/return goal. There are no facial/eyeball controls.

World targets must be 0.25..10 metres from the entry head and inside its angular
envelope. A coincident or near-vertical target is rejected because the upright roll
reference would be undefined. Desired gaze uses +Y forward and the closest world-up
+Z reference. The actual current head position, rather than the entry point alone,
determines direction during tracking; torso turning/bending therefore does not convert
a world point into a body-relative point. No torso motion is generated by head.look.

## Capability-scoped neck behavior

`catalog_for_profile(profile)` returns these five definitions with profile-scoped neck
ownership. On the Mixamo rig, neck.lead owns the real head and neck and requires their
measurement capabilities. The demo has no Neck bone. Its definition owns only head and
is tagged `head_only_approximation_requires_opt_in`; the default require_neck still
fails MISSING_CAPABILITY with the explicit head_only alternative. Nothing silently
pretends that a missing neck moved.

`neck_policy=head_only` must be explicitly supplied to execute that approximation.
Its fragment contains `head_only_approximation` at time zero, and contains no neck
tracks. A capable rig can also request this intentionally. The production global
catalog retains the full-neck definition; use the profile-scoped catalog when offering
the explicitly labelled fallback. No bone or capability is fabricated.

## Opt-in calibrated profile extension

Existing calibration v1/profile fixtures remain unchanged. Call
`calibrate_joint_frames(..., include_head_aim=True)` or the pure
`spatial.with_head_aim_v1(profile)` to obtain **profile version 2**. It preserves all
existing mappings, axes, ranges and controls and adds:

| Control | Shape/unit/frame | Independent measurement |
| --- | --- | --- |
| head.position | vector3, metre, world | Actual calibrated head origin |
| head.orientation | quaternion [w,x,y,z], unitless, world | Actual head semantic frame, +Y forward/+Z up |
| head.torso_orientation | quaternion, unitless, current_torso | Current uppermost torso rotation removed from actual head semantic rotation |

The current torso is spine.upper, otherwise spine.mid, otherwise torso. The extension
has explicit `head_aim_v1:world_position_world_and_torso_orientation` provenance. Binding
accepts v2 only with that marker and the existing skeleton/scale fingerprint; unrelated
profile versions still fail. Old v1 measurements/execution do not opt in implicitly.

Nod/shake/tilt and local neck lead can use the original scalar controls. head.look
requires the v2 orientation/position capabilities. Snapshot values are actual measured
orientations, never the requested point relabelled as a measurement.

## Versioned curve extension and migration

The common schema remains v1 with one explicitly versioned additive extension:
`CurveSpec.look_at_world_v1`, an optional world-metre vector3. It is valid only on a
quaternion world-framed head.orientation TrackSpec. Start/end values remain orientation
quaternions. The optional field declares that the destination is resolved each sample
from the measured head position and this fixed world point. Transition uses the existing
smooth quaternion slerp; hold keeps tracking the point. The same binding resolves its
orientation goals, which are then compared with actual achieved orientation.

Absent/None fields use the original curve semantics and serialize **byte-for-byte in
the old shape**. The updated reader explicitly permits this one absent extension field;
all other canonical fields, units, frames, duplicate keys and versions stay strict.
Generated CurveSpec/TrackSpec/MotionFragment/ExecutableMotion JSON schemas mark this
field optional. All original v1 fixtures still decode/round-trip unchanged. Readers
predating this extension reject an extended saved curve's unknown field; do not remove
it to make a world-target clip appear compatible. Recompile with the current bridge.

A world look's return uses a measured-entry activation binding to the achieved tracking
pose. Its hold goal is sampled before release, so a moved parent cannot cause a return
to jump back to an entry-time predicted quaternion. Runtime bindings stay per-run.

## Shared execution and review

These builders return the same MotionFragment and use prepare_fragment/sample_motion
and the existing build_action_frames transaction. The adapter applies explicitly authored
parent scalar tracks, captures that frame's actual head position, and resolves orientation
through the same sampler and cursor. It does not add a separate execution/keyframe loop.
Scalar and orientation ownership of head in the same fragment is rejected as a conflict.

The head orientation solver changes only the calibrated head rotation; it does not
reset neck/torso or alter the rest skeleton. Independent post-solve measurements and
normal floor/contact/speed/acceleration checks remain enabled. Phase goals use 0.1-degree
tolerance, stricter than the shared 3-degree limit. Shared 0.5-degree/2-mm unrelated
target limits, 3-mm floor and 25-mm contact limits are unchanged.

The developer harness now accepts production IDs without --test-catalog, opts into
profile v2 and selects its profile-scoped catalog. For example, from C:/work11:

```powershell
'{"yaw":-30,"return_policy":"return_to_entry"}' | Set-Content artifacts/stages/05.1a/parameters.json
& 'C:\Program Files\Blender Foundation\Blender 5.1\blender.exe' `
  --background --factory-startup --python-exit-code 1 --python tools/preview_movement.py -- `
  --id head.look --version 1 --parameters-file artifacts/stages/05.1a/parameters.json `
  --rig demo --entry tests/fixtures/movement_fragments/v1/entry-bent-turned.json `
  --output-dir C:/work11/artifacts/stages/05.1a/cli-preview --render
```

The family test harness has explicit parent-turn fixtures, not a generic composer.
Each output directory has input records, every solved sample and a real keyframed
preview.blend. Front/side sheets read left-to-right, top-to-bottom. The receipt and
movement ledger record the actual reviewed rigs/cases and remaining limits.
