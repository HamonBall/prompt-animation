## Plan

Implement smooth/fluid, robotic/staccato, heavy, light/playful, exaggerated and tired as scoped transformations of verified movements.

**Permitted changes:** Pattern/style definitions and composer-facing style transforms; focused semantic-preservation and visual tests.

## Execution

1. Define each style's permitted parameter/curve changes: amplitude, anticipation, hold, timing, easing and follow-through. Store numeric bounds and compatibility requirements in the registry.
2. Apply styles to specified instances/chains. Explicit user target/path/contact requirements override optional style preferences; incompatible styles return a conflict.
3. Keep smoothness independent from global speed. Use deliberate bounded pauses for robotic style, and a reproducible pattern for light/playful motion rather than random per-frame jitter.
4. Retain source-instance IDs and a style parameter record so 'more fluid' or 'less exaggerated' can become a narrow edit later.

Record defaults/ranges, frames, entry/return policy, owned chains and reviewed rig envelope per ID. Test every baseline variant, min/max and invalid inputs with measured and full-motion visual evidence; metadata alone is not implementation.

Optional anatomy needs explicit missing-capability tests.

## Testing

- Compare a neutral arm stroke, a step and a torso pattern under supported styles; inspect visible differences across the full motion.
- Assert unchanged explicit endpoints, travel direction, support schedule where locked, and unrelated chain targets. Measure speed/acceleration after each transform.
- Test conflicting styles, zero/maximum intensity and a style requested on an unsupported movement.

## Validation / completion gate

Each of the six style families has a specific transformation, tested envelope and visible effect. All explicit locked goals remain satisfied; styling cannot bypass normal geometry/motion review.

Write the stage-05.7b receipt with commands, measured results and inspected artifacts. Update this stage's index status only after its required gates pass.

## Restraints and exclusions

No unbounded noise, global timing changes for a local style request, physics claims or adding scenery. 'Heavy' may use timing/posture cues but does not imply a mass simulation.
