# Stage 13.1 — Review collisions against complete objects

Status: planned. Dependencies: [13](13-object-builder.md).

Read [00-START-HERE.md](00-START-HERE.md), [object/contact/collision contracts](contracts/04-object-contact-collision.md) and completed prerequisites. Implement only this document. Object contact is not equivalent to clearance against the entire object.

## Plan

Provide a bounded collision-review service for static generated props before motion-object interaction is advertised. Detect avatar intersections with seats, backs, legs and other supported geometry, including crossings between sampled poses.

**Permitted changes:** new blender/object_collision.py, shared geometry queries and motion-review integration; object proxy/collision records; focused tests. Preserve the existing rig solver and generated-object budgets.

## Execution

1. Implement prepare_collision_scene(), review_object_collisions() and review_swept_interval() from the contract. Cache static object acceleration/proxy data by object version; rebuild after transforms or geometry change.
2. Use broad-phase bounds to select candidates, then appropriate mesh intersection/containment checks for supported generated shapes. Detect intersections even when no avatar vertex is inside the object. Floor/seat-only vertex minima cannot satisfy this requirement.
3. Add conservative swept limb/body proxy checks between samples. Refine flagged intervals with at most four bisections and 2,048 candidate proxy pairs per interval initially. Return collision_uncertain/resource-limit when these bounds prevent classification; never return clear by default.
4. Apply contact tolerance only to the intended supporting part and surface region. An acquired seat permits the declared pelvis-seat contact, not arm penetration through the chair back or leg.
5. Add issues to the existing normal/experimental review policy with part, object, interval, method and actual measurement when available. Boolean intersection is not an invented penetration-depth value. Preserve candidate rollback and cancellation.

## Required outputs and handoff

Publish the implemented method/geometry coverage and policy schema in the stage receipt. Save reproducible chair-leg, back-panel, containment, edge-crossing and between-frame fixtures under tests/fixtures/object_collision/. Stage 14 must call this service using the resolved object versions; a visual-only proxy producer is insufficient.

## Testing

- Create tests/test_object_collision.py for analytic/policy cases and tests/blender_object_collision.py for actual avatar/prop geometry.
- Include valid seated contact, collision with a thin back/leg, an edge crossing with vertices outside, full containment, movement through a prop between samples and a clear near miss.
- Test transformed objects, expired caches, refinement-budget exhaustion, cancellation and preservation of the previous result.
- Inspect full-motion evidence on demo/imported rigs and rerun supported floor/seat regressions.

## Validation / completion gate

Every mandatory collision fixture is detected or conservatively marked uncertain; clear fixtures pass without disabling intended contacts. Normal reviewed output cannot include unresolved prop clearance. Report measured tolerances and false-positive cases; do not claim complete arbitrary-geometry collision detection.

Write the stage-13.1 receipt with commands, metrics and inspected artifacts; update its status only after required gates pass.

## Restraints and exclusions

No rigid-body response, automatic obstacle avoidance, moving/rigidly grasped props, wall support or full avatar self-collision solver. Do not alter avatars, suppress whole supporting objects or skip between-frame checks to claim speed. Stage 17 tunes costs while preserving this coverage.
