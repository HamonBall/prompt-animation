## Implementation and version boundary

Nine movement definitions use the existing validated fragment/compiler/sampler
and transactional Blender bridge. The new implementation is
`src/avatar_app/movement_library/hands.py` and
`src/avatar_app/blender/hand_mechanics.py`. Compiler supporting chains, calibrated
measurements and executor ownership were extended only as required for these IDs.
`docs/contracts/elbows-wrists-hands-v1.md` describes the API and coordinate frames.

`with_hands_v1` explicitly opts into profile **5**. Definition version remains 1;
contract/compiler and storage schemas retain their existing versions. Profiles
1–4 retain their measurement meanings and fixtures. A fresh calibration/entry is
required; editing a snapshot's version is not migration. There are no finger
gestures, automatic surface attachments, prompt-specific handlers or generic
recipe composer. Optional twist bones are not synthesized or driven without
calibration. The reviewed core forearm bones exist on both rigs.

All IDs offer left/right/both, independent side overrides, duration 1.5..3 s
(default 1.5), hold 0..1 s (default .1), and return_to_entry (default) or
preserve_end. Spatial goals have a conditional reach/clearance envelope rather
than a blanket guarantee over all coordinates. Hard incompatibility rejects
before accepting a replacement. Nonselected body/root/legs/arm motion is preserved.

## Per-ID delivery

### elbow.flex

Default 45 degrees; absolute geometric hinge angle 0..130, straight=0. The
upper-arm-relative lower-arm hinge preserves measured forearm twist; supporting
hand motion follows the lower arm. It owns the selected forearm chain, not an
upper-arm rotation used to fake flexion. Cases include neutral/overhead entries,
zero/min/max, timing, sides, independent overrides and return policies.

### elbow.orient

Default +20 degrees; entry-relative pole offset -45..45 about shoulder-to-wrist.
It jointly owns the selected upper arm, forearm and palm to preserve world wrist
position and orientation. An entry bend below 3 degrees rejects ENTRY_MISMATCH;
the near-straight reviewed fixture stays above that boundary. This is a bend-plane
preference, not sideways elbow hinging. Stationary-wrist and signed range cases
check actual pole and endpoint measurements throughout.

### forearm.twist

Default +45 degrees supination; signed absolute range -179..179 avoids the
ambiguous signed-180 branch. The sign comes from calibrated bind anatomy,
independent of current elbow bend. It owns the selected forearm axial rotation;
wrist flexion/deviation are measured independently and preserved. Actual palm-up
and palm-down goals cover straight and bent arms and opposite bilateral normals.

### wrist.flex

Default +20 degrees, range -60..60; positive toward the palm using each rig's
anatomical wrist frame. Only selected wrist orientation is edited, retaining
deviation and axial state. Wrist endpoint and forearm path remain unchanged.
Both-rig cases include a 90-degree body turn and overhead parent orientation.

### wrist.deviate

Default +10 degrees, range -25..25; positive toward the thumb. It uses the same
independent wrist solve, preserving flexion/axial state and the authored arm path.
Signed limits, bilateral asymmetry, turned-body and overhead cases distinguish
local anatomy from global Euler axes.

### wrist.circle

Default signed radius +5 degrees, range -10..10. A 32-chord phase orbit is tangent
to entry, with flexion excursion 0..2*radius and deviation +/-radius; no root
travel is declared. It owns the wrist only. Complete-cycle pose/endpoint/contact
and angular-velocity seams are audited, including zero and signed extremes.

### hand.orient

Default entry-relative palm roll +30 degrees, range -150..150, or explicit unit
quaternion. +Y is finger-forward, +Z palm-normal; `spatial.palm_rotation` constructs
this reference. World, entry-body and current-torso orientation parameters are
distinct and schema-labelled. It owns selected wrist orientation with bounded
support where required; incompatible independent hard palm/twist controls reject.
Opposite hands and actual palm-normal/finger-forward evidence distinguish this
from forearm twist.

### hand.trace

Default line distance +.02 m, range -.04...04; shared line/arc/circle curves.
World `target`, entry-body `entry_target`, and current-torso `torso_target`
(including side prefixes) are explicitly typed. Defaults capture the current
wrist. Arc/circle axes follow the documented entry-body or torso convention.
It owns the coordinated selected arm and palm. Every sampled target must satisfy
reach, joint, speed, contact and clearance gates. Arc/circle signed range cases
are additional to the primary matrix; circles also require loop-seam checks.

### hand.hold

Default captured wrist/palm, with explicit world/entry-body/current-torso position
and orientation goals and independent side overrides. It owns the coordinated
selected arm and palm. Optional hard `flexion_deg` must agree with the geometric
endpoint; incompatible values reject CONSTRAINT_CONFLICT. Optional poles can be
soft (omit an undefined straight-arm plane) or hard (reject it). A torso-motion
fixture distinguishes world-fixed from torso-following behavior. Chest-height
wrists with forward elbows are authored using torso targets and poles, with no
sentence-specific branch. This is free-space holding, not contact.
