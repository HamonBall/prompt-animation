## Version resolution and next-stage limits

This is the first implemented library schema, v1. Resolved additions to the proposed
contract include recipe avatar/profile versions; profile controls/height; parameter
dimensions/nullability/control linkage; definition phase/return policies; explicit
parameter provenance for instances/styles and exact style definition version; finite
LoopSpec and typed patch/binding/provenance records. Every nested record persists its
schema version. Canonical serialized records include all fields/defaults/nulls. Unknown
versions fail with a migration message; no migration is silently applied.

unchanged. Their callers require no adapter yet. `motion.py` remains a module. Future
curve kinds and root trajectory extensions must version their serialized meaning.
